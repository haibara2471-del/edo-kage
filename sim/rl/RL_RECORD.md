## 演化历史

### v0.42（胜利导向 + 存活工资 bug）
击杀 +100 / 承伤 0.1（残血放大）/ 时间 **+0.05×frames（符号反，=每步 +0.2 存活工资）**。
**结果**：EV 0.9+ "假健康"，蹲到 timeout 净赚 +180，胜率 0%。——时间惩罚符号 bug（v0.35 修过，v0.42 重写 reward 复发）。

### v0.43（修符号 + 击杀反通胀 + 承伤回落）
- 时间 `+0.05*frames` → `-0.05*frames`（-0.2/步）——修复存活工资
- 击杀 +100 → +50；承伤 0.1 → 0.05（保留残血放大 1x/2x/3x）
- 训练=random / 测试=waves 纪律恢复
**结果（回放确认）**：单足轻/对空 100%，但足轻×3 同侧 → **边退边镖** timeout（镖 spam + 发呆，6 血残敌收不掉）；两侧散开 → 边跑边挥刀刀刀砍空，1059 帧死、总伤害仅 13。**根因：击杀 +50 尖峰在 norm_reward 下把 dense 信号压成噪声。**

### v0.44（数值经济重排，用户确认）
- 击杀 +50 → **+15**；承伤 0.05 → 0.03（误判，下版撤回）；时间 -0.2 → **-0.4/步**
**结果（回放确认）**：行为从"边退边镖"**翻转为"冲进敌群换血"**——890 帧死、总伤害仅 12（刀全 whiff）。wave2 1/10 → 2/10。证明"逼终结"方向对，但承伤 0.03 让**换血无成本**：脸接 90 伤只亏 2.7，模型没有避伤梯度。

### v0.44b（避伤梯度——承伤是主杠杆，用户判断）
- 承伤 0.03 → **0.15**（5×，去残血放大）。其他不动。
**结果（回放确认）**：**基础战斗全部毕业**——
  - 足轻×3 同侧：0% → **100%（639 帧满血）**
  - 足轻×2+弓+钩：0% → **100%（316 帧）**
  - 真局 wave2：1/10 → **7/10**
  - 完整三波：0% → 0%，但**清完 wave1 后卡在"推进触发下一波"**（停在 x=98 发呆 2500+ 帧 timeout）

### v0.45 → v0.45c（advance 推进机制，用户设计——三连失败，已定位）
- 推进奖励：advance 阶段（清场后）右移 1px +0.15（260px ≈ +39）
- random 课程掺入推进分支教 advance（waves 仍是测试集）
- **v0.45**（25% 分支，wave1→推进→wave2 硬编成，maxTicks 4800）：足轻×3 100%→**0%**、wave2 70%→10%，但弓+钩/单足轻仍 100%
- **v0.45b**（15% 易版 wave1→推进→wave1，maxTicks 4800）：弓+钩 100%→**0%**、wave2 0%，更崩
- **v0.45c**（15% 易版，maxTicks 回 3000 隔离）：单足轻 **0%**、足轻×3 0%，但弓+钩 100%、wave2 20%，**waves 能打到 wave2 了**（advance 机制真的学会了）
- **结论**：
  - ✓ advance 机制可学（v0.45c waves 回放打到了 wave2，总伤害 180）
  - ✗ 所有掺 advance 的训练都崩基础战斗（whiff 复发，单足轻 891 帧仅 12 伤）
  - maxTicks 3000→4800 **不是**元凶（v0.45c 回 3000 仍崩）
  - 三个变体崩的场景各不相同 → **单次 300k 训练方差很大**，v0.44b 的好结果可能部分靠运气
- **根因假设（未验证）**：advance 奖励 +0.15/px 在推进期产生密集 +2/步的强正样本，撑大 norm_reward 的方差 → 压缩战斗 dense 信号（伤害/承伤）→ whiff 复发。与击杀尖峰是同一机制，只是换了个来源
- **方向**：见「当前问题与设计」

## 关键平衡考虑

### 为什么承伤 0.15（主杠杆）
- **0.03 的失败**：挨 1 点 -0.03 vs 砍 1 点 +1.0（刀）→ 换血 30 倍赚。模型没有理由躲，站 3 敌中间吃集火，890 帧死。
- **0.15 的效果**：挨一次足轻攻击（10 血）= -1.5，砍中一刀 = +12 → 躲开挨打的边际价值 ≈ 1.5/12 ≈ 12%，**避伤梯度真实存在**。回放验证：模型学会"隔离-逐个击破"（先单杀最右足轻、再回头打剩下两个），满血/半血清场。
- **为什么不加残血放大**：v0.43 教训——残局承伤放大（1x/2x/3x）会吓退模型近战收尾。只加基础倍率，让避伤与输出平权。
- **副作用（已知未修）**：fast-death 结构——时间惩罚 vs 死亡惩罚：撑到 timeout(3000帧) ≈ -350，快速送死(890帧) ≈ -139。打不赢时模型必选送死。修法需动时间/死亡比值（时间 -0.25 或死亡 -100），但**一旦模型能赢（+190），送死梯度自然消失**，暂不单独修。

### 为什么击杀 15
- norm_reward（按回报标准差归一）下，击杀 +50 尖峰把 dense 信号压成噪声：时间 -0.2 → 归一后 -0.06、刀伤 +1 → +0.28，击杀仍大 ~50 倍 → 模型梯度只剩"敌人死了=大奖励"，学不到贴身终结。
- +15 = 半只足轻的刀伤价（30 血 × 1.0 = 30），仍显著但不压灭 dense。
- 收残敌边际：+15 击杀 vs 拖着 = 时间持续在亏（-0.4/步）→ 逼收尾。

### 为什么时间 -0.4/步
- -0.2/步归一后 ≈ -0.06，形同虚设（v0.43 边退边镖就是"拖死也不急"）。
- -0.4/步成功逼出攻击性（边退边镖消失）。代价：见承伤 0.15 的副作用（fast-death）。

### 为什么推进奖励 0.15/px（v0.45）
- advance 是"清场后向右走 260px 触发下一波"的机制，reward 必须让右移有即时梯度。
- 0.15/px → 260px ≈ +39 ≈ 0.3 波清场价值，足够显著又不喧宾夺主。
- 模型需要 obs[39]（advance 特征，(目标-x)/1000，>0 表示前方有指示）——训练中推进分支让该特征从恒 -1 变为真实值，模型才能学会"有指示就向右"。

## 当前问题与设计

### 1. waves 推进（advance）机制（v0.45 已动）
**现象（回放确认）**：v0.44b 清完 wave1 后停在 x=98 发呆 2500+ 帧，不向右走触发下一波，timeout（卡住帧 4090/5400）。
**根因**：random 课程是一对一房间战，advance flag 恒为 -1（obs[39]），模型从没见过"有指示要向右走"。浏览器端有硬编码 hack（AiInput 无敌时按住右）绕过了它，但模型本身没学会。
**设计（用户定）**：
- 环境清场后自然给出前进指示（obs[39] > 0）
- 推进期给推进奖励（右移 +0.15/px）
- random 课程掺入推进分支（25%），waves 仍为测试集

### 2. Boss 战（0%）
200 血 + 复杂招式，~1800 帧被打死。基础战斗 + 推进解决后单独立项（现有 boss/bossSquad 场景可训）。
